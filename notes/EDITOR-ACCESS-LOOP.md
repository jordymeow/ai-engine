# Editor Access for MCP (OAuth), iteration log

Started 2026-09-14 after meteorlxy's wp.org request (topic "Let an OAuth-authorized MCP session inherit the authorizing user's own cap"). Jordy asked for a careful implementation, then a loop of at least 20 passes before the end of the day: test, check for regressions, keep the UI consistent and easy to understand, refine.

## What was built (uncommitted until Jordy says so)

- Setting **Settings → MCP → Editor Access** (`mcp_oauth_editors`, default off).
- `labs/mcp-oauth.php`: `user_can_authorize()` admits `edit_others_posts` users when the setting is on; refusal message and consent note adapt; consent shows "Editor (content only)".
- `labs/mcp.php`: OAuth users without `manage_options` get `$limited_session`: tool list and calls restricted to `LIMITED_SESSION_TOOLS`, and `limited_session_refusal()` checks each call against the user's own capabilities (read_post, edit_post, publish, post type create, term caps, comment caps, upload_files, no server paths for vision).
- Upload endpoint uploads as the requesting user (`user_id` stored by `wp_upload_request`).

## Test fixtures on ai.nekod.net

- Editor user `mcp_editor_test` (ID 19).
- OAuth token row for user 19 (client "Test Client"), plaintext token only in the job tmp dir (`editor_token.txt`), never in the repo.
- Scripts (job tmp dir): `editor_matrix.py` (22 allow/deny checks), `editor_upload.py`.
- Admin regression: `node labs/tests/test-smoke.js mcp`.
